# third_party_base_libs Orchestrator Recipe Management

## Overview

This skill guides the agent in inspecting, auditing consistency, updating, and maintaining the **third_party_base_libs** build recipe. `third_party_base_libs` uses the `csorchestrator` framework to define cross-platform third-party base-library build pipelines in Python and generate corresponding GitHub Actions CI workflows.

## Dependencies

- **Python**: `>= 3.11` in active `.venv`
- **csorchestrator**: Available as an editable package in the local environment
- **Tools**: `pre-commit`, `ruff`, `mypy`, `pytest`

## Quick Start

To audit recipe consistency and re-generate the GitHub Actions CI workflow:

```bash
# 1. Re-generate GitHub Actions workflow from third_party_base_libs_project.py
./third_party_base_libs_project.py generate-github-workflow

# 2. Run quality checks and ensure git hygiene
pre-commit run --all-files
```

## Workflow

Follow these steps when interacting with or modifying the `third_party_base_libs` build recipe:

### 1. Recipe & Consistency Audit
Inspect the core configuration files before making changes or upon request:
- [`third_party_base_libs_project.py`](file:///home/sceriani/myWorkspace/third_party_base_libs/third_party_base_libs_project.py): Core pipeline definition, version, and repository list.
- [`pyproject.toml`](file:///home/sceriani/myWorkspace/third_party_base_libs/pyproject.toml): Project metadata and versioning.
- [`third_party_base_libs/csorchestrator_config.py`](file:///home/sceriani/myWorkspace/third_party_base_libs/third_party_base_libs/csorchestrator_config.py): Compiler and toolchain mappings (currently a placeholder).
- [`tests/`](file:///home/sceriani/myWorkspace/third_party_base_libs/tests): Placeholder tests; real recipe tests are added later.

**Verification Checklist (Strict Fail-Loud Policy):**
- **Extra Files**: Check every path passed to `additional_files_list` in `create_default_orchestrator()` (e.g. `Path("third_party_base_libs/csorchestrator_config.py")`). Verify that every referenced file exists on disk.
- **Version Alignment**: Verify that `version` in `third_party_base_libs_project.py` (e.g. `0.1.0`) aligns with `version` in `pyproject.toml` and artifact package names (`third_party_base_libs-<version>-...`).
- **Repository List**: Verify that every repository in `repos` is a known csorchestrator-supported repo and that its `BuildConfig` (`RELEASE`, `DEBUG_RELEASE`, or `None` for checkout-only repos like `csCMake`) matches the repository's intended configuration.
- **SDK Vendoring**: `csorchestratorsdk/portable/` is autogenerated from `csorchestrator`; do not edit manually. If it needs updating, re-export it from `csorchestrator`.

> [!IMPORTANT]
> If any consistency check fails (missing extra file, mismatched version, unknown repository), **fail loudly**. Report the exact discrepancies to the user for guidance rather than silently continuing or guessing.

### 2. Local Execution Policy (Build Guard)
- **DO NOT run full local builds of all base libraries** (e.g., executing all phases of `./third_party_base_libs_project.py` locally). Building every library on the full matrix requires significant time, disk space, and RAM.
- Only run unit tests (`pytest`) or dry-run validation when checking local configuration logic.

### 3. CI Workflow Re-generation
Whenever `third_party_base_libs_project.py`, the repository list, or execution phases are modified, re-generate the GitHub Actions workflow:

```bash
./third_party_base_libs_project.py generate-github-workflow
```

- Verify that [`.github/workflows/third_party_base_libs.yml`](file:///home/sceriani/myWorkspace/third_party_base_libs/.github/workflows/third_party_base_libs.yml) has been updated with the modified phases and matrix.
- Inspect the git diff using `git diff .github/workflows/third_party_base_libs.yml` to ensure changes match expectations.

### 4. Code Quality & Pre-commit Verification
Before concluding any changes, run the repository's validation hooks:

```bash
pre-commit run --all-files
```

If hooks report formatting errors or auto-fix lines:
1. Review the modified files.
2. Re-run `pre-commit run --all-files` to ensure all checks pass cleanly (`Passed`).

### 5. Documentation Synchronization
If recipe arguments, version, or repository configurations were updated:
- Update [`README.md`](file:///home/sceriani/myWorkspace/third_party_base_libs/README.md) to keep the included-libraries table, build matrix, and command instructions accurate.

## Common Mistakes

1. **Attempting a full local build**: Running `./third_party_base_libs_project.py` without understanding that it will attempt to download and build all base libraries. Full builds are meant for CI runners or dedicated build machines.
2. **Forgetting to re-generate the workflow**: Modifying `third_party_base_libs_project.py` without running `./third_party_base_libs_project.py generate-github-workflow`, leaving `.github/workflows/third_party_base_libs.yml` out of sync with the Python recipe.
3. **Missing extra files in release**: Adding a file to `additional_files_list` in `third_party_base_libs_project.py` that does not exist or has a typo in its relative path, causing release packaging jobs to fail in CI.
4. **Version mismatch**: Updating `version` in `third_party_base_libs_project.py` without updating `pyproject.toml` or the artifact names (`third_party_base_libs-<version>-...`).
